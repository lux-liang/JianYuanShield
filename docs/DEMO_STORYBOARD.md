# 鉴源盾现场演示分镜（完整版 4.5 分钟 / 答辩版 3 分钟）

## 演示原则

现场只讲一条主线：登记一张图片，破坏它，再验证它，最后篡改证据让系统主动拒绝背书。四模型状态、统计图和供应链材料都是主线的证据，不单独堆页面。

## 0–30 秒：提出冲突

- 屏幕：原图、平台压缩图、删除元数据图并排。
- 台词：“这三张图在人眼看来相同，但文件哈希全部不同；其中一张元数据已被删除。传统哈希和单一元数据在传播后都会失效。”
- 评委获得的信息：问题真实且直观。

## 30–75 秒：生成数字出生证

- 客户端生成或加载创作者设备密钥。
- 请求一次性挑战并完成签名。
- 选择当前可信模型执行保护。
- 下载受保护图片和 `source-credential.json`。
- 展示内容编号、创作者公钥指纹、checkpoint 指纹和 AIGC 标识检查。

必须说清：私钥留在客户端；服务端验证的是持钥证明，不是接收一段自报身份文本。

## 75–125 秒：传播后核验

依次验证三种输入：

1. 原始保护图：四项结论均通过；
2. 压缩图：`exact_protected_file_match=false`，但水印可能仍恢复；
3. 删除元数据图：`aigc_metadata_intact=false`，不把水印恢复偷换成合规标识完整。

讲解重点：系统把字节、内容、标识和声明拆分为四种清晰语义。

## 125–160 秒：撤销而不抹除历史

- 服务端签发一次性撤销意图；
- 原创作者密钥签名；
- 再次核验同一图片；
- 展示 `verified=true` 仍可保留，但 `claim_valid=false`。

讲解重点：撤销以可验证追加事件实现，完整保留历史记录。

## 160–210 秒：多水印冲突治理

- 打开 MEA 4×4 矩阵；
- 选择一个方向性 cell，解释 A→B 与 B→A 的差异；
- 展示身份 cluster bootstrap 下界与推荐策略；
- 调用后端 recommend，让评委看到推荐不是前端写死。

讲解重点：单模型准确率回答不了多平台重复嵌入问题。

## 210–255 秒：最有记忆点的证据熄灭

- 展示当前 release-core 验签通过；
- 使用预制、隔离的篡改副本修改一项 summary 或签名；
- 重新执行 evidence audit；
- 页面将正式声明降级为 `review_required`。

安全要求：只能修改演示副本，不修改正式 runtime 原件。演示结束后删除副本。

## 255–270 秒：收束

如严格限制三分钟，应将 MEA 压缩到 20 秒，并在 170 秒开始收束：

> 鉴源盾为 AI 内容建立贯穿传播、撤销与证据变更的可信来源链。

## 现场失败预案

| 故障 | 切换方案 | 不可做的事 |
|---|---|---|
| GPU 模型加载慢 | 使用预热服务和已登记样例做盲核验 | 切换到假模型后仍声称正式结果 |
| 网络不可用 | 使用离线镜像与本地 sidecar | 临时下载依赖 |
| 小程序域名受限 | 切换同源 Web 客户端 | 在前端写死成功结果 |
| 某模型不可用 | 展示 capability unavailable 与门禁 | 静默回退模拟数据 |
| 现场时间压缩 | 保留登记、压缩核验、证据熄灭三个动作 | 逐页念架构和指标表 |

## 演示前检查单

- release-core 签名已独立验真；
- 三个 canonical benchmark 链接均指向正式 run；
- API Key、签名者指纹和 provenance secret 通过文件注入；
- 正式 evidence 目录只读；
- 篡改演示使用临时副本；
- 准备一张原图、保护图、压缩图、去元数据图和 sidecar；
- 预热主模型；
- 浏览器清缓存后完整走一遍；
- 录制 90 秒兜底视频，但现场优先真实操作。
