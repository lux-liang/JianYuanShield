# 评委问答

## 这是普通 Deepfake 检测吗？

不是。系统强调主动取证：在内容传播前嵌入可恢复信息，并在攻击后评估能否恢复来源与水印。

## 这些模型是否只是外部开源项目？

不是。LIDMark、MEA、WaveGuard、KAD-Net 均属于本团队原创技术体系，经指导教师同意在鉴源盾中统一集成。鉴源盾新增了统一协议评测、证据审计、交互闭环和报告体系。

## 哪些结果是真实 checkpoint？

四模型均真实 checkpoint，完成 13,233 张 LFW 全量评测，并在 19 万张真/假人脸上验证跨数据集与 AIGC 泛化。
- **KAD-Net**（EC_50）clean/jpeg/平台 ≥99%（真/假脸一致），旗舰；几何为该架构限制（系统由 HiDDeN 覆盖，见几何问答）。
- **WaveGuard**：原始 model_state_16 在真实 uint8-RGB 往返下 clean≈72%（权威"100%"是无往返的乐观值）；**经自重建 STE 噪声层联合微调后，uint8+JPEG 下 ~72%→~100% 并泛化到未训练的 webp/亮度/对比度**（信号鲁棒已修复）。
- **SepMark**（EC_115）bit-acc≈85-89%。
- **HiDDeN**（epoch-300）：JPEG 偏弱，但**几何鲁棒（crop/rotate 94-96% 且跨参数泛化）**，是系统的几何覆盖模型。
- **LIDMark**：landmark 定位 99.93%；**16-bit ID 完整配置（face_alignment 真实 landmark）正测 clean 99.8%/jpeg50 99.9%≈100%**——更正了早先 MEA 模式（landmark 置零 OOD）测得的"≈随机 62%"测量假象，id 溯源实为强项。

## 为什么 HiDDeN 指标不高还要展示？

这是信息安全评测的价值：同样是真实 checkpoint、同样是真实 LFW 数据和攻击链路，HiDDeN 在当前域上恢复接近随机，说明公开 watermark checkpoint 不能直接假定可迁移。SepMark 在同一条件下明显更稳，构成强弱对照。

## 当前最适合答辩的模型是哪一个？

四模型均已完成正式 checkpoint 评测，按场景推荐如下：

- **LIDMark（核心亮点）**：landmark 定位 99.93% + **16-bit ID 完整配置 ~100%（clean 99.8%）**，语义绑定（人脸关键点+用户 ID）是独创亮点，竞赛辨识度最高。
- **KAD-Net（比特精度首推）**：EC_50，LFW 全量 clean/jpeg/noise/resize ≥99%，且跨数据集（真/假脸）一致，**对 AI 再生成天然部分鲁棒**。几何为架构限制，须诚实说明（由 HiDDeN 覆盖）。
- **WaveGuard（鲁棒性修复示范）**：自重建 STE 噪声层联合微调后 uint8+JPEG ~72%→~100%；**并作为对抗式再生成硬化的载体**（见再生成问答）。
- **HiDDeN（几何鲁棒）**：crop/rotate 94-96% 跨参数泛化，系统几何覆盖。
- **SepMark**：LFW 13,233 张（pre-trained checkpoint EC_115.pth），bit-acc≈85-89%（clean=87.74%）；success@0.9 为 59-72%（128-bit 长消息）；"decoder_RF 91.2%"偏高，以 ~88% 为准。

## 为什么 WaveGuard 有多个接近 100% 的指标？

当前结果来自真实 checkpoint 全量推理。我们已完成严格权重加载以及错误消息、无嵌入图像负对照：正确消息为 100%，两个负对照约为随机水平，因此没有发现明显消息泄漏。但现有攻击偏弱，仍不能直接宣称绝对领先。

## 为什么要做 MEA？

MEA 多重嵌入攻击体现信息安全攻防：攻击者可以通过二次嵌入或平台水印覆盖原始取证信号，导致溯源失败。

## 结果是否做了统计显著性分析？

已对 SepMark（13,233 张）逐图配对结果生成 Bootstrap 置信区间、配对符号翻转检验、效应量和 Holm 多重比较校正。LIDMark 的置信区间来自 3 个独立 seed（共 512×3=1,536 张，同一批 512 图重复 3 次），注意：这 3 个 seed 使用同批图像，between-seed 方差为训练随机性，建议配合互不重叠的更大样本重测。LIDMark 当前上报的"精度"为 landmark 定位成功率（99.93%），ID 比特精度评测进行中。WaveGuard 当前 n=13,233 全量，统计分析完整。

## 报告如何防篡改？（诚实口径：完整性自校验 + 来源签名，演示级）

诚实定位：这是**完整性自校验 + 来源数字签名（演示密钥，Ed25519）**，**不是"司法级防篡改证据链"**。

- **完整性自校验**：用 Ed25519 对一份 canonical evidence manifest 签名，manifest 记录协议、诊断、统计、报告和 checkpoint 等文件的 SHA-256（覆盖文件数以 `evidence_audit` 接口实际返回的 `evidence_files` / `file_count` 为准，README 与本文件引用数字以接口真实返回为准）。前端可下载 manifest、签名和公钥；修改任意已覆盖文件都会触发 `content_mismatch`。
- **追加式弱链（prev_hash）**：manifest 携带上一份 manifest 的 SHA-256（`prev_hash`）与单调递增 `record_seq`，构成轻量 append-only 链，便于发现历史 manifest 被整体替换。**但这不是 Merkle 树，也无外部可信锚定，仅为演示级弱链。**
- **来源签名**：演示用 Ed25519 私钥由**运行方现场生成**（`chmod 600`）、**绝不入库**，对外只导出公钥；私钥与验签器同机、无 HSM/密钥托管，仅作演示。

诚实局限（答辩时主动说明，不夸大）：

- **时间戳取本机时钟**（manifest `time_source='local_clock'`、`generated_at` 为本机 `time.time()`），**非 RFC3161 可信时间戳机构（TSA）背书**，可被持机者伪造，**不具备法庭证明力**。
- prev_hash 弱链只防"局部篡改 / 历史替换"，持私钥方可重签整条链；取得宿主机控制权即可重新签发任意 manifest。
- 完整威胁模型与做实路线见 `docs/THREAT_MODEL.md` §五。

## 对手能去掉或绕过你的水印吗？（威胁模型诚实口径）

能，**部分能**——我们已建模三档对手并如实标注失效边界（完整版见 `docs/THREAT_MODEL.md`）：

- **被动观察者**：仅读不改图。已做负对照（错误消息/无嵌入图≈随机），未发现明显消息泄漏；无私钥则无法篡改证据。
- **主动去水印者**（多数攻击已迭代防御，残余如实标注）：
  - 几何（裁剪/旋转）：单看 KAD/WaveGuard 失效，但**系统由 HiDDeN 覆盖**（crop/rotate 94-96% 跨参数泛化）——用对模型即可溯源。
  - JPEG/uint8 往返：WaveGuard 经自重建 STE 噪声层微调后 ~72%→~100%（且泛化 held-out 信号攻击）；KAD 本就 ≥99%。
  - **AI 再生成**：对抗式硬化后在 held-out（未见）再生成器上 0.3%→68% 存活；残余代价为 PSNR↓（半可见）。
  - 多水印二次嵌入（MEA）：仍是红队发现的真实失效（first_acc≈0.5），列为后续。
- **自适应攻击者（白盒）**：对抗训练目前只覆盖再生成族；对**新型扩散净化 / 白盒对抗扰动**仍预期偏弱，正用 E1–E4 evasion 量化（THREAT_MODEL §四）。

诚实结论：**经本轮迭代，几何/JPEG/uint8/AI 再生成 等主要攻击已分别由"用对模型"或"对抗硬化"防御并验证泛化**；残余真实边界为：纯隐形场景下的再生成抗性有限、多水印覆盖、白盒自适应攻击。我们把每项防御与残余都附 n / 对照 / held-out 进表，**不掩盖攻防边界**——这正是信息安全作品该有的诚实姿态。

## KAD-Net 的当前评测状态？

KAD-Net 已完成 GEOM 微调（checkpoint EC_50.pth），**LFW 13,233 张全量**评测结果：
- clean：bit-acc=**99.98%**，jpeg50=99.09%，jpeg70=99.79%，jpeg90=99.97%，noise=99.93%，resize=99.97%
- **几何攻击（已知硬限制）**：crop_center_0.8=68.92%（success=1.14%），rotate_5=43.73%（success=0%）——即便 GEOM 微调后仍实质失败

MEA 矩阵 KAD-Net↔WaveGuard 对角线外相对兼容（KAD→WG: 100%|100%，WG→KAD: 100%|100%），但 KAD→KAD first_acc=50%（自鲁棒性失效，与单模型 clean 100% 矛盾，口径 bug 排查中）。

## WaveGuard 在 JPEG-50 压缩下成功率为什么只有 37%，而 JPEG-70 是 99%？

**完整解释**（已做梯度实验验证）：

WaveGuard 使用 DTCWT（双树复小波变换）频域嵌入水印。JPEG 压缩对不同频段的量化阈值不同：
- WaveGuard 主要使用**高频子带**（LH/HL/HH）嵌入信息
- 高频子带的 JPEG 量化阈值约在 q≈60-65 处
- 原始权重 q=50 时高频子带被量化，detector 成功率 37.3%
- q=70 时高频子带受到保护 → detector 成功率 99.6%

我们对 50 张图像做了 q=40→90 的梯度实验，结论一致（q=60: 93%, q=70: 99.7%）。

**当前状态（model_state_16，n=13,233 全量）**：jpeg50 bit-acc=88.97%，但 **success@0.9=37.3%**（真弱点）；jpeg70/jpeg90/noise/resize≈100%；clean=100%。主流平台（q=75-85）始终≈100%。jpeg50 改进进行中，不可称"已修复至100%"。

## HiDDeN 的失效是域偏移还是别的原因？

HiDDeN 使用 **epoch-300 checkpoint**，完成 **n=13,233 全量评测**。结果：clean bit-acc=99.05%（好），resize=98.07%（好），noise=93.31%（中等）；**JPEG 系列失败**：jpeg50 bit-acc=57.09%、success=0%——这是**域 gap**（训练域与测试 LFW 的 JPEG 处理差异）。

HiDDeN 是**有效对照 baseline**，在同一评测框架下揭示了不同水印方案对 JPEG 攻击的鲁棒性差异，与 KAD-Net/WaveGuard 形成强弱对照。它**不是"损坏/已剔除"**——那是对一个更早的坏 checkpoint（epoch-200）的错误描述。答辩时可主动展示：同一评测框架下，HiDDeN 的 JPEG 局限 vs. KAD-Net/WaveGuard 的 JPEG 鲁棒性，体现平台的多模型横向对比价值。

## 为什么要用 3 个 seed 并行训练 LIDMark？

单 seed 的 Bootstrap CI 只反映图像采样不确定性，不能排除训练随机性带来的结果偏差。3 个独立 seed 可以：
1. 计算跨 seed 均值和方差，证明结果稳定性
2. 通过 Holm 多重比较校正，控制误报率
3. 向评委展示团队的科学性严谨程度——"我们知道一次实验不够，所以主动做了三次"

## 几何攻击（裁剪/旋转）你们解决了吗？

**系统层面解决了，且我们诚实地证明了"为什么用对模型而不是强改一个"。** HiDDeN（CNN 嵌入）在 crop 0.7–0.9、rotate ±3–±10° 上全部 **94–96%，且跨参数泛化**（已用未训练参数验证）——这是真几何鲁棒。对 DTCWT 子带水印（KAD/WaveGuard），我们**试了四种**改造（固定参数微调、随机范围训练、解码端模板重同步、可学习 STN）全部失败：根因是任何空间 warp（攻击或矫正）都破坏子带水印，**几何不变性无法在解码端事后修补、必须在嵌入端**。所以多模型系统的设计就是"按攻击面用对模型"，这本身是经实验论证的结论，而非回避。

## 你们的水印能扛住 AI 再生成（扩散/AE 重生成）吗？

这是现代去水印最强的攻击，基线下我们的水印再生成后成功率≈0。我们做了**对抗式硬化**（把自训练 AE 再生成纳入对抗训练），关键是**用完全未参与训练的 held-out 再生成器验收**：在**从未见过的再生成器**上，存活率 **0.3%→68%、bit-acc 0.60→0.91**——证明是真泛化、不是记忆某个再生成器。诚实代价：再生成是强有损攻击，要存活水印必须够强，PSNR 从 24 降到 ~14（半可见），这是 imperceptibility↔robustness 的**内禀权衡**；我们给出可选工作点，不宣称"零代价解决"。

## 系统能定位篡改区域吗？

能。全局消息水印做不到（实测遮挡法 AUC≈0.5；landmark 位移法表面 0.94 经对照证伪为中心先验假象）。我们改用**分块独立水印**：每个空间块嵌入独立水印，被篡改块自身水印被破坏→逐块比特准确率即定位篡改区，**grid4 AUC 0.948**。真实性用三档对照证实：clean 各块准确率均匀 0.905、篡改区内块 0.55「«」区外块 0.87（与位置无关），所以不是"中心先验"假象。

## 怎么保证你们的结果不是夸大或过拟合？

这是我们项目最看重的一点：**每个"解决"都内置对照/泛化护栏，并据此多次主动推翻了会被误判为"已解决"的结论**——
- 篡改定位 landmark 位移法 AUC 0.94，加均匀权重对照后真实增益≈0（中心先验假象）→ 我们没有把它当成果；
- 几何固定参数微调 crop_0.8→0.99，但 held-out 参数全≈0.5（参数记忆）→ 我们如实标注为"记忆非鲁棒"；
- 再生成硬化用 held-out 再生成器排除"记忆单一 AE"。

所有失效项都进表、附 n 与对照口径。**这种"先证伪自己"的严谨，本身就是信息安全作品应有的姿态，也是评分应看重的科学性。**
