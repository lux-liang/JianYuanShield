## 1. 使用前必读

1. 只上传本人有权处理的图像，不要上传未授权的人脸、身份证件或其他敏感内容。
2. 系统核心功能是对“已登记记录”进行来源水印匹配，不是对任意图片进行真假鉴定。
3. `verified=true` 只表示恢复水印达到登记阈值；只有 `claim_valid=true` 且结果场景正确时，才表示通过当前系统的完整技术门禁。
4. 技术门禁通过不等于自然人实名已核验、事件具有可信时间戳或材料必然获得司法采信。
5. 公网使用必须通过经验收的 HTTPS 地址。仓库中有 TLS 反向代理配置不代表当前打开的地址已通过证书验收。

## 2. 账号与角色

V1.0 后端使用 `X-API-Key` 作为最小部署访问控制，尚未建立完整的用户、角色和租户级权限体系。部署管理员应通过网关或客户端运行时设置提供短期访问凭据，不得将长期 API Key 写入 Web 页面、小程序源码、Android 安装包、URL 或截图。

| 角色 | 建议操作 |
| --- | --- |
| 内容创作者 | 对授权原图建立持钥登记，保存受保护图与来源凭证 |
| 登记核验人员 | 用内容编号或凭证对待核验图片进行匹配，完整保留原始响应 |
| 评测人员 | 查看固定协议的模型评测、MEA 冲突矩阵和证据门禁 |
| 部署管理员 | 配置密钥、权重、校准、签名指纹、TLS、备份和最小权限 |

## 3. 访问系统

### 3.1 Web 可视化系统

1. 使用现代浏览器打开部署方提供的 HTTPS 地址。
2. 确认浏览器地址栏中的域名和证书正确，不忽略证书告警。
3. 页面载入后首先查看服务健康、GPU 连接、模型状态与证据状态。
4. 若页面显示“连接中”、“能力不可用”、`review_required` 或 `unverifiable`，不要将展示数字视为当前可发布结论。

当前仓库的前端契约测试仅将 KAD-Net 设为 `provenance_ready` 正例。页面可列出四种模型，但只能选择 `/api/models/status` 实时标记为 `provenance_ready=true` 的模型；不要以为代码中有模型名称就代表该模型已受信。

### 3.2 Android 客户端

1. 安装由部署方签名的 release APK，不使用来历不明的重打包版本。
2. 在“服务器设置”中填写 HTTPS 基础地址和部署方发放的短期令牌。release 版不允许明文 HTTP。
3. 首次登记时，客户端在设备上创建 Ed25519 密钥材料，并使用 Android Keystore 中不可导出的 AES-GCM 包装密钥保护私钥。
4. 备份或换机可能无法迁移密钥。丢失密钥后不能代表原创作者对对应记录执行持钥撤销，请按部署方的密钥丢失流程处理。

### 3.3 微信小程序

小程序必须使用微信合法 HTTPS 域名。后端地址和演示令牌可通过 `extConfig` 注入，但小程序中的静态令牌可被提取，不能当作长期秘密。当前小程序保护请求未完成创作者一次性挑战字段提交，不应用它声明已完成持钥证明。

## 4. 正式创建来源保护登记

### 4.1 前置检查

- 确认原图的处理权限；
- 确认后端处于预期环境，公网上传使用 HTTPS；
- 确认目标模型 `provenance_ready=true`；
- 确认客户端能执行一次性创作者挑战，当前建议使用 Android 客户端或按 API 契约实现的受控客户端；
- 准备 1–128 个可打印字符的 `creator_ref`。该字段是应用引用，不是实名证件。

### 4.2 Android 操作步骤

1. 进入“登记核验”页。
2. 选择本人有权处理的图片。
3. 输入创作者应用引用。
4. 点击“创建来源保护登记”。
5. 客户端在本地计算原图 SHA-256，将公钥、引用、模型和图像哈希提交给 `/api/creator/challenges`。
6. 客户端验证返回内容并在本地对 canonical challenge 签名，再将 `challenge_id` 与签名一同提交给 `/api/provenance/protect`。
7. 等待水印嵌入和登记完成。不要重复提交同一挑战，因为挑战只能消费一次。
8. 保存返回的受保护 PNG、`content_id` 和 `.jys-credential.json` 来源凭证。建议在两个独立位置备份，并记录哈希。
9. 检查响应中的 `creator_identity_verified`、`claim_valid`、`evidence_status` 和 `audit_ledger`。若任一关键门禁未通过，只能将记录视为运行性产物。

### 4.3 Web/小程序展示流程的限制

当前 Web 和小程序可执行直接 `protect → verify` 界面流程，但它们尚未将客户端挑战签名字段接入保护请求。在生产模式下，后端应对缺少挑战的保护请求返回能力错误；在非生产模式下，记录可被创建，但 `creator_identity_verified=false` 且不应用于正式持钥声明。

## 5. 核验已登记内容

1. 准备待核验图片，保留其原始字节，不要为了上传而再次截图或转码。
2. 准备对应 `content_id` 或来源凭证。若二者同时提交，其中的编号必须一致。
3. 在“登记来源核验”区域选择图片，输入编号或导入凭证，然后发起核验。
4. 检查响应中的模型和检查点哈希是否与登记一致。
5. 按下表解读结果，不要只截取单个数字。

| 字段 | 为 `true` 时的准确含义 | 不能推导的结论 |
| --- | --- | --- |
| `exact_protected_file_match` | 待核验字节与登记的受保护文件完全相同 | 不证明上传人是创作者 |
| `verified` | 恢复消息达到该记录和模型阈值 | 不证明图片从未被编辑 |
| `aigc_metadata_intact` | 已实施的 AIGC 元数据和封印检查通过 | 不自动构成监管合规认定 |
| `claim_valid` | 当前系统定义的身份、权重、校准、签名、审计和撤销门禁同时通过 | 不证明自然人实名、可信时间或司法效力 |

6. 保存完整 JSON 响应、待核验文件、来源凭证及各自 SHA-256，不要仅保存页面截图。

## 6. 下载、导入与独立保存来源凭证

- 保护响应包含凭证下载地址和 Base64 内容；Android 客户端可导出 `.jys-credential.json`。
- 凭证包含登记记录、创作者证明、审计和撤销状态的绑定信息。修改其中任何字段会导致签名或定位校验失败。
- 凭证不包含创作者私钥。如果文件中出现私钥、长期 API Key 或密码，立即停止分发并按泄露事件处理。
- 无法从受保护图或凭证恢复创作者私钥。

## 7. 撤销记录

撤销是不可恢复的业务操作，只应在创作者确认原因后执行。

1. 在 Android 客户端选择对应的登记记录。
2. 选择撤销原因：`creator_request`、`key_compromise`、`mislabeling` 或 `policy_violation`。
3. 请求一次性撤销意图。
4. 使用创建记录时的同一设备密钥签名。
5. 提交撤销并保存返回的撤销事件。
6. 重新查询记录，确认历史水印恢复事实仍可查看，但当前 `claim_valid=false`。

若记录创建时没有完成有效的创作者密钥绑定，系统应拒绝持钥撤销；管理员不得伪造创作者签名。

## 8. 查看证据、声明和评测

1. 在证据页查看签名状态、公钥指纹、清单成员和错误原因。
2. 在声明页查看每一项 claim 的状态、证据路径和限制。
3. 在 MEA 页查看固定 4×4 实验矩阵、Pareto 结果和部署建议。建议只适用于其签名样本、协议和模型集，不是跨数据集通用结论。
4. 在模型评测页先读取评测协议、样本数、正负对照和置信区间，不直接比较不同消息长度或解码语义的原始 bit accuracy。
5. 任何证据成员缺失、哈希变化或签名指纹不一致时，按 fail-closed 结果处理，不使用历史页面缓存替代证据。

## 9. 常见状态与处理

| 页面/API 状态 | 含义 | 建议处理 |
| --- | --- | --- |
| `checkpoint_unavailable_or_hash_mismatch` | 权重缺失或实际哈希与登记值不一致 | 停止保护，由管理员核对受控权重目录 |
| `checkpoint_unregistered` | 权重未命中审批清单 | 不手动跳过，完成清单审批与签名 |
| `calibration_unverified` | 缺少身份隔离的校准产物或哈希不匹配 | 执行固定校准流程，不自行输入阈值 |
| `weight_manifest_untrusted` | 权重清单、证据包或固定签名者未通过 | 核对 release-core 与带外指纹 |
| `capability_unavailable` | 所请求的盲检等能力尚未实现或未校准 | 显示“不可判定”，不解读为无水印 |
| `review_required` / `unverifiable` | 证据不完整或发生漂移 | 保留现场并由审核人重新验签 |
| HTTP 401/403 | 缺少、错误或无权的访问凭据 | 重新获取短期凭据，不在聊天或工单中发送长期密钥 |
| HTTP 413/422 | 文件过大、像素过多、字段或图像不合法 | 核对原文件和字段，不为绕过限制而修改服务端 |
| HTTP 503/504 | 模型或证据未就绪、队列已满或推理超时 | 查看健康与 GPU 状态，避免密集重试，通知管理员 |

## 10. 隐私、留存与安全建议

- 保护流程不将原图写入来源资产目录，但上传数据会经过请求内存和 multipart 处理；受保护图、内容哈希、创作者应用引用和核验事件会持久化。
- 单图工程评估的衍生产物有默认 TTL，来源记录和受保护图当前没有完整自动删除政策。部署方必须另行建立保留期、删除申请、备份到期和日志脱敏规则。
- 不共享 Android 应用数据、私钥包装文件、API Key、服务端签名私钥或 provenance secret。
- 保存来源凭证时同时保存当时的签名公钥指纹和带外核验记录。

## 11. 交付验收建议

1. 用全新授权测试图片完成 Android 持钥挑战、保护、凭证导出和核验。
2. 检查服务端不保存原图，检查受保护图、数据库记录和审计锚点位置。
3. 使用原始受保护图核验字节精确匹配，再使用一个受控转码版本检查水印结果和字节结果的分离表达。
4. 篡改凭证中一个字段，确认验签失败且界面不保留旧的可信结论。
5. 使用错误、过期和已消费的挑战，确认系统拒绝。
6. 验证 HTTP 到 HTTPS 跳转、证书链、HSTS、上传大小、鉴权和日志脱敏；不仅检查配置文件。
7. 将验收时的 Git commit、容器 digest、权重/校准哈希、签名指纹、测试输出和异常情况写入交付记录。
