# 《鉴源盾内容来源可信取证系统 V1.0》原创与第三方边界说明

## 1. 文件目的

本文件用于软件著作权登记准备和内部权利复核，区分鉴源盾内容来源可信取证系统 V1.0 的平台实现与集成的第三方模型、代码、权重、数据集及依赖。它是工程边界说明，不是对所有权利关系的最终法律意见。

著作权人、开发人员、职务成果、合作/委托开发和权利转让情况必须由申请人根据合同、任务书和实际开发事实确认。GitHub 仓库归属、账号名或仓库可见性不能单独决定权利归属。

## 2. 本项目拟申报的平台实现范围

以当前仓库可复核代码为基础，软著材料聚焦下列平台层实现，具体作者与权利人仍需由申请人逐个文件/提交复核：

| --- | --- | --- |

| 来源保护、登记、核验和撤销编排 | `system/backend/provenance.py`、`routes.py` | 对水印模型的组织、记录、事件和信任门禁；不包含底层水印网络原理 |
| 主动水印统一适配契约 | `system/backend/model_adapters.py`、`system/evaluation/adapters/` | 平台适配、输入输出与错误语义可作为集成代码复核；底层模型归上游 |

| 身份隔离评测、统计和证据校验 | `system/evaluation/`、`system/scripts/`、`scripts/` | 评测协议、运行组织、校准/留出分割和证据重算；模型结构、公开数据与第三方攻击模型仍归上游 |

上表说明“拟纳入平台实现复核”，不代表表中每个文件已完成作者和雇佣/委托关系的法律审查。最终提交前必须使用 Git 历史、代码来源、合同与作者声明逐项复核。

### 3.2 预训练权重

所有 `.pth`、`.pt`、`.ckpt`、`.onnx` 等预训练权重或导出模型均不应因平台调用而被声明为平台原创。权重的训练来源、作者、数据授权和再分发权必须单独核验。哈希清单只证明所用字节版本，不会生成新的权利。

### 3.3 数据集、人物图像与实验产物

- Labeled Faces in the Wild（LFW）及其中图像不属于本项目；
- CelebA/CelebA-HQ 及其派生材料不属于本项目；
- 人物图像还可能涉及肖像权、隐私、数据保护和原图片版权，源码许可不会覆盖这些权利；
- 原始实验图、换脸产物、热力图、个人头像、截图与评测结果不因位于运行目录而自动成为软著源码。

默认软著包必须排除数据集、运行时报告/资产、个人图像和常见图像/音视频文件。如登记材料需界面截图，应在包外使用专用合成数据重新生成，并保存授权与脱敏记录。

### 3.4 框架、软件包与前端 vendor

Python 包、PyTorch、FastAPI、OpenCV、Android/Jetpack、Google Tink、Gradle、Docker 基础镜像、Caddy 以及其他直接/传递依赖都归各自作者和许可人。`system/frontend/vendor/heic2any.min.js` 是第三方 vendor 文件，默认软著源码包将整个 `vendor` 目录排除，同时保留第三方通知文档用于审查。

`requirements.lock`、CycloneDX SBOM、Gradle 依赖声明和容器构建清单是第三方组件识别证据，不表示上游作者为本项目背书。

## 4. 平台集成与底层算法的区分方法

对任何涉及模型的文件，建议按下列问题判断是否纳入软著材料：

1. 文件是否直接从上游复制或属于上游冻结目录？是则不纳入原创源码。
2. 文件是否实现本平台定义的统一适配、哈希门禁、证据绑定或业务流程？是则可进入开发事实复核。
3. 文件是否包含上游网络定义的大量复制，或只对上游代码做小量修改？是则需保留上游通知、变更说明并由顾问判断派生作品边界。
4. 文件的作者、开发任务、时间和权利归属是否有记录？没有则先补证，不因位于本仓库而推定。
5. 删除该文件后，本平台的自有编排逻辑是否仍可清晰辨识？软著鉴别材料应优先展示可独立辨识的平台代码。

## 5. 可以声明与不应声明的典型表述

| 可用的限定表述 | 不应使用的扩大表述 | 原因 |
| --- | --- | --- |
| 平台实现了四种第三方水印模型的统一适配和信任门禁 | 平台原创了四种水印算法 | 统一适配不改变底层算法归属 |
| 当前仓库契约仅确认 KAD-Net 为 `provenance_ready` 正例，运行时以状态接口为准 | 四种模型都已受信并可用于正式来源保护 | 适配器可用不等于权重、校准和证据全部通过 |
| 后端与 Android 已实现一次性创作者持钥挑战 | 所有三端的每次登记都已完成持钥证明 | Web 和小程序直连保护尚未提交挑战字段 |
| 仓库提供边缘 TLS 终止和 HTTP 重定向配置 | 当前所有入口必然已使用受信 HTTPS | 证书、DNS 和运行时拓扑必须现场验收 |
| Ed25519 证明指定密钥对 canonical 字节签名并可检测篡改 | 签名自动证明自然人身份、可信时间和司法效力 | 这些需要外部身份、时间和取证程序 |
| 评测结论限于固定协议、检查点、数据和签名证据 | 对所有数据、平台和攻击都具有领先鲁棒性 | 固定实验不能外推到未测分布 |

## 6. 软著源码包的默认排除策略

`scripts/build_software_copyright_package.py` 生成软著源码包时采用保守默认值，包含可读的平台源码、配置、测试和说明文档，排除：

- 仓库外挂载或根目录的 LIDMark、KAD-Net、MEA、SepMark、WaveGuard、SimSwap 等第三方模型源码；
- `vendor` 目录、模型权重、检查点、导出模型和归档文件；
- 数据集、运行时 `data/assets/reports/runs`、SQLite 和实验产物；
- venv、cache、build、dist、日志、备份与编辑器/系统临时文件；
- `.env`、PEM/密钥库、密钥、本地属性、运行凭据和包含私钥头的文件；
- 常见图片、音频和视频文件，以避免将人脸、头像或不明权利素材进入包体。

该工具将生成 `SOURCE_MANIFEST.tsv` 和 `SHA256SUMS`，使最终包中的文件集可审查、可重算。排除策略是减少误交付风险，不是对剩余文件权利状态的法律保证。

软著源码包仅用于源程序审查，不是仓库中“国赛离线交付包”的替代品。需要复现模型的受控发行包应在授权范围内另行携带上游 LICENSE/README、冻结源码、权重、证据和完整物料清单。
